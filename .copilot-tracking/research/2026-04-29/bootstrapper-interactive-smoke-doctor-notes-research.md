# Bootstrapper Interactive Smoke Doctor Notes Research

## Scope

Continue all four suggested items from the prior Phase 5 output:

1. Add Release Bootstrapper.
2. Add Interactive UI Smoke.
3. Add Doctor To Browser Settings.
4. Generate Release Notes From Changes Logs.

## Difficulty

Medium-hard. The work spans Windows startup, package metadata, browser UI behavior, CI browser installation, release workflow behavior, release notes generation, and validation.

## Findings

* `start.bat` currently starts the compiled UI with `npm run serve` but does not check Node or install dependencies for release archive users.
* `scripts/ui-smoke.js` already has an interactive Playwright branch, but the repository does not install Playwright, so CI falls back to static smoke.
* Settings already contains connection and media tool controls, while first-run setup has a health check using `/api/setup/health`.
* Release workflow currently relies on `softprops/action-gh-release` generated notes. Changes logs exist locally under `.copilot-tracking/changes`, but they are not tracked in git by default.
* A release notes script should read `.copilot-tracking/changes` when present and fall back to concise package notes when absent, so local and CI flows both work.

## Selected Approach

* Expand `start.bat` into a release bootstrapper that checks Node/npm, runs `npm ci` when dependencies are missing, builds if compiled output is missing, and starts `npm run serve`.
* Add `playwright` as a dev dependency and install Chromium in CI before `npm run smoke:ui`.
* Extend `scripts/ui-smoke.js` to verify it is running interactively when Playwright is available and to click both first-run and Settings setup doctor controls.
* Add Settings doctor controls to `ui/index.html` and `ui/app.js`, reusing `/api/setup/health`.
* Add `scripts/release-notes.js` to generate `release/release-notes.md` from `.copilot-tracking/changes`, with a fallback when no changes logs exist.
* Update release workflow to generate release notes before publishing and pass the file to `softprops/action-gh-release`.

## Success Criteria

* Release archive startup is beginner-friendly on Windows.
* CI runs interactive Playwright UI smoke instead of static-only smoke.
* Settings exposes reusable setup doctor output.
* Release workflow publishes notes generated by the repository script.
* Local and remote validation pass.
